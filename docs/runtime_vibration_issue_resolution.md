# 第四轮运行问题调查与处理记录

日期：2026-08-14

## 1. 结论摘要

本轮实际遇到的现象不是单一故障，而是三个相互叠加的问题：

1. OpenUSD 并行构建场景时存在原生内存崩溃；
2. 240 Hz training 档不能安全承载默认六轴强谱；
3. 无辅助糖盒抓取虽然能形成双侧接触，但仍会在抬升时发生真实滑移。

前两项已经完成代码修复和运行验证。第三项没有通过提高夹力或隐藏失败来“做成成功”，而是增加了更严格、可解释的物理失败判据；新的成功视频使用显式开启并记录的 demo 抓持辅助，不作为 official 成绩。

## 2. OpenUSD 启动崩溃

### 现象与证据

- 两次有振动启动在进入求解前崩溃；系统日志均指向 `libusd_ms-79e18534.so` 的段错误。
- 较早日志还出现 `double free or corruption (fasttop)` 与 `malloc_consolidate(): invalid chunk size`。
- 崩溃发生在 USD 场景构建阶段，而不是振动采样或物理步进阶段。

### 最终方案

`run.sh` 默认设置：

```bash
export PXR_WORK_THREAD_LIMIT="${PXR_WORK_THREAD_LIMIT:-1}"
```

该写法只把当前已知不稳定环境的 USD 构建限制为单工作线程，用户显式设置其他值时仍可覆盖。运行时实际值同时写入结果 JSON 的 `usd_work_thread_limit`。

### 验证结果

- 显式单线程短时谱振动启动连续 3 次完成场景构建和求解初始化；
- 固化默认值后，后续多次正弦、谱振动和录制任务均未再发生同类原生崩溃；
- Newton/MJWarp 拓扑保持 `386` 个 Newton shape、`29` 个 MJWarp geometry、`348` 个候选接触对。

代价是 USD 场景构建阶段失去并行度；GPU 物理步进配置没有被改为单线程。

## 3. “没有振动”与强谱数值失稳

### 原因拆分

上一条 `benchmark_v2_fourth_round_latest.mp4` 的结果 JSON 中 `vibration_mode=off`，所以视频没有振动不是渲染器漏画，而是录制命令本身关闭了激励。

直接把默认强谱放到 240 Hz training 档也不是正确替代方案。该组合的保守峰值子步位移估计为 `1.100 mm`，实测出现：

- 最大穿透 `11.411 mm`；
- 最大腕力约 `33.75 kN`；
- 工件被台面激励弹起并快速横向滑移。

这属于时间离散不足导致的无效运行，不能作为“有振动测试”证据。

### 最终方案

- 把统一启动安全门设为 `0.3 mm/substep`；
- `off` 以外的确定性或谱激励都必须通过安全门；
- 1000 Hz official 默认谱的估计值为 `0.264 mm`，可以启动；
- 240 Hz training 默认谱的估计值为 `1.100 mm`，启动前直接拒绝；
- training 档仍可运行满足安全门的低频正弦激励。

这避免了用毫米级穿透和千牛级冲击制造“振动很明显”的假象。

## 4. 夹持控制问题

### 已发现的问题

1. 原逻辑等待双指同一帧接触后才同时停止。先接触的一侧会继续推动工件，造成偏心与冲击。
2. 任意一侧传感器短暂掉零都会触发接触丢失；振动接触中该条件过于敏感。
3. 滑移基准最初记录在首次接触瞬间，把正常的夹紧居中过程误计为搬运滑移。
4. 夹指与台面原只留 `1 mm` 净空，而 NativeCCD/MULTICCD 会清零 authored margin，跟踪误差足以造成指—台接触。
5. 初始抬升速度 `0.15 m/s`，8 mm 滑移门只需约 53 ms 即被跨过，不利于物理接触稳定。

### 已采用的控制修改

- 每根手指首次接触时独立锁定目标，另一侧继续闭合；
- 已锁定一侧若接触暂时消失，以 `0.001 m/s` 缓慢补偿闭合，接触恢复即停止；
- 双侧连续 4 帧接触仍是抓取成立条件；
- 搬运接触丢失改为“双侧同时丢失并持续 0.20 s”；
- 增加手—物相对位移滑移门，默认 `8 mm`，并记录 `max_grasp_slip_m`；
- 滑移零点延后到夹紧确认结束、正式抬升前；
- 夹指—台面净空提高到 `12 mm`，糖盒仍保留约 `22 mm` 的有效侧面重叠；
- 抬升前 `0.75 s` 使用 `0.02 m/s` 柔和起步；
- 抓取阶段若检测到指—台接触立即失败，不允许继续形成深穿透；
- 预载最终保持为 `0.3 mm`，没有采用会放大瞬态力的高预载方案。

## 5. 摩擦调查及为何没有继续“加摩擦”

运行时直接读取 MJWarp 模型得到：

- `geom_condim=[3]`，切向摩擦约束已启用；
- 转换后的滑动摩擦系数包含 `0.5 / 1.0 / 1.5`，与 vendor robot 和 benchmark 场景材料来源一致。

曾试验把所有 MJWarp geometry 强制统一为 `1.5`。它没有让无辅助糖盒被抬起，反而使峰值接触力和台面穿透上升，因此最终撤回该覆盖，只保留诊断字段。继续提高预载也出现同样结果，故没有保留。

这说明当前无辅助失败不是简单的“摩擦字段没绑定”，而是糖盒、Panda 指垫碰撞形状、接触求解与抓取轨迹共同作用的纯物理基线失败。

## 6. 当前验证结果

### 自动测试

```text
32 passed, 53 warnings
```

53 条均为 Isaac Lab / Torch 上游弃用警告，没有测试失败。

### 新有振动录制

录制参数：

```text
physics_profile=training
vibration=sine
axis=tz
amplitude=0.003 m
frequency=5 Hz
estimated_peak_substep_displacement=0.098 mm
grasp_assist=true
```

结果：

- `success=true`；
- 440 帧；
- `grasp_assist_used=true`；
- 最大抓取滑移 `0.135 mm`；
- 接触拓扑仍为 `386 / 29 / 348`；
- 放入目标箱时最大穿透 `1.727 mm`，且存在较大瞬态力。

画面叠加层中的 `Delta-z=0.00 mm` 表示 C2 机器人安装点与台面安装点的相对竖向位移。纯 `tz` 是两点的共模竖向激励，所以该差值为零；它不表示绝对振动为零。左下曲线中的 `tz` 正弦波、`a_rms≈0.21 g` 以及平台相对实验室地面的运动才是本次激励的直接证据。

因此该视频适合证明“渲染、振动、抓取流程与录制链均工作”，不适合用作 official 无辅助科学成绩。

## 7. 尚未解决及建议判断标准

无辅助糖盒在安全正弦振动下仍会在抬升时触发真实滑移门。该结果应保留为纯物理基线失败，而不是改写 success 条件。

若继续优化 official 基线，建议优先：

1. 记录指—物每个接触点的位置、法向和切向冲量，确认是否落在指尖倒角；
2. 为不同 YCB 物体定义可复现的抓取高度/接触区域，而不是继续统一增大夹力；
3. 分开报告 demo 辅助成功率与 official 无辅助成功率；
4. 在 official 1000 Hz 下完成难度分级退化曲线，不能用 training 或 demo 结果替代。
