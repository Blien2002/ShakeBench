# ViBench — 第二轮改造提示词（基于实际渲染帧诊断）

对齐对象：`out/benchmark_v2_wrist_camera_fixed.mp4`（1280×720 / 30 fps / 14.33 s / seed=17）
前置文档：`docs/prompts/round1_scene_refactor_prompt.md`（第一轮）

---

## 0. 诊断结论：问题不是"建模不够精细"

对视频第 5.5 s 帧的中央场景区（像素范围 `[200:520, 300:900]`，避开四个叠加面板）做统计：

| 指标 | 实测值 | 含义 |
|---|---:|---|
| 亮度均值 | 149 | 整体偏亮 |
| 亮度标准差 | 35 | 偏低 |
| 亮度四分位间距（P25→P75） | **131 → 152，仅 21 灰阶** | 半数像素挤在 21 个灰阶里 |
| 落在 [120, 215] 窄带的像素 | **73.8%** | 层次严重压缩 |
| 饱和度 < 0.08 的像素 | **68.5%** | 场景近乎无彩 |

**结论：当前场景的根本问题是明暗层次崩塌，而不是几何细节不足。**

platen 顶面、platen 侧面、基坑内壁、基坑底、Stewart 腿、工作台桌腿这六类表面，在画面上的亮度全部落在 130–155 之间。在这个动态范围内，即使把螺纹孔阵列、倒角、铭牌全部贴上去，也不会产生可见的视觉收益——细节会被冲平。

因此本轮的执行顺序必须是：**R1 层次重建 → R2/R3 修 bug 级几何 → R4/R5/R6 加细节 → R7 构图**。跳过 R1 直接做 R4 是浪费工作量。

## R0 — 建立可量化的视觉回归基线

```
在动任何视觉代码之前，先建立一个客观、可重复的视觉质量度量，
避免后续改造靠"感觉好像好看了一点"来判断。

新建 tools/visual_audit.py，功能：
1. 输入一个 MP4 或一张 PNG，指定一个中央场景 ROI（默认 [200:520, 300:900]，
   即避开四个叠加面板的区域），输出：
   - 亮度 min / max / mean / std
   - 亮度分位数 P1/P5/P25/P50/P75/P95/P99 和四分位间距 IQR
   - 落在 [120,215] 窄带内的像素占比
   - 饱和度均值和低饱和（<0.08）像素占比
   - 一张亮度直方图 PNG
2. 支持 --baseline 模式保存当前结果，和 --compare 模式做前后对比表格。

先对现有的 out/benchmark_v2_wrist_camera_fixed.mp4 第 5.5 s 帧跑一次，
存为 docs/visual_baseline.json。当前基线实测值为：
  mean=149, std=35, P25=131, P75=152, IQR=21,
  窄带占比=73.8%, 低饱和占比=68.5%

后续每一轮改造完成后都要重跑并对比。本轮的总目标是把
IQR 从 21 提升到 ≥ 60，std 提升到 ≥ 55，窄带占比降到 < 50%。
```

## R1 — 明暗层次重建（最高优先级）

```
当前场景所有表面的亮度都挤在 130–155 之间，这是"看起来不精细"的根本原因。
本条分三部分，全部做完再看效果，不要只做一部分。

【第一部分：材质明度重新规划】

给场景里每一类表面分配明确的目标亮度（0–255 感知亮度），拉开层次。
建议方案（可微调，但相邻层级的亮度差必须 ≥ 25）：

  机械臂本体          215   （已接近，保持）
  工作台桌面          200
  房间墙面            195
  目标收纳盒          180
  platen 顶面         150
  木地板              130   （已接近，保持）
  工作台桌腿/框架     110
  platen 侧面          95   ← 关键：必须和顶面拉开 55 灰阶，制造立体感
  Stewart 作动器筒     78
  惯性基座 / 基座平台  62
  基坑内壁 / 基坑底    48   ← 关键：基坑必须明显暗于地面，才有"深度"

注意 platen 顶面(150) vs 侧面(95) 和 platen 侧面(95) vs 基坑壁(48) 这两组，
是当前完全没有区分、但对立体感贡献最大的两组。

实现方式取决于第一轮 P0 的 NewtonGL 能力探测结论：
- 若 UsdPreviewSurface 的 diffuseColor 生效（几乎肯定生效），直接调 diffuseColor。
- 若 roughness/metallic 不生效，则把不同表面的高光差异也烘进 albedo 贴图。
- 侧面和顶面若属于同一个 box prim 无法分别赋色，就把 platen 拆成
  "顶板 + 侧裙" 两个 prim，或改用带每面材质的自定义 mesh。

同时给场景加入一点色相区分，当前 68.5% 像素饱和度 < 0.08 太单调：
  platen / 作动器 → 略偏冷（蓝灰，色相偏 210°）
  惯性基座 / 基坑 → 中性偏暖灰
  木地板 / 墙面   → 保持暖色
冷暖对比会让金属件从环境里"跳出来"，但饱和度整体控制在 0.10–0.20，
不要做成彩色场景。

【第二部分：假接触阴影（收益仅次于第一部分）】

NewtonGL 关闭了硬投影阴影，这是所有物体呈悬浮感的直接原因。
实现 spawn_contact_shadow_decal()，沿用 visual_assets.py 里
author_textured_quad() 的 0.2 mm 封闭 UV 薄网格方案（已验证兼容 MJWarp）。

需要投影的对象和落点：
  工作台四条桌腿      → 投在 platen 顶面
  目标收纳盒          → 投在 platen 顶面
  工件（sugar_box）   → 投在 platen 顶面，需每步跟随
  机械臂底座          → 投在 platen 顶面
  platen 整体         → 投在基坑底
  护栏立柱            → 投在木地板

贴图用径向渐变软阴影，中心不透明度 0.45，边缘 0。
工件抬起后按高度衰减：不透明度 ∝ exp(-h/0.15)，半径 ∝ (1 + h/0.20)，
让"抬起"这个动作在阴影上可读——这在振动 benchmark 的视频里是有信息量的。

所有阴影贴片 collision 禁用，改造前后接触对数量增量必须为 0。

【第三部分：打光重调】

当前 sky(0.30,0.30,0.30) / ground(0.22,0.22,0.22) / 曝光 1.15 / 镜面 0.22。
建议：
- sky/ground 比值拉大到 0.36 / 0.14，强化"上方来光"的方向感。
- 曝光从 1.15 降到 0.95。当前桌面大理石纹理被冲白到看不见，就是过曝导致的。
- 增加一盏低强度背光（从机械臂后上方 30° 打），做轮廓分离。
- 镜面强度从 0.22 提到 0.30，让金属件有一点点高光。

【验收】
跑 tools/visual_audit.py，要求 IQR ≥ 60、std ≥ 55、窄带占比 < 50%。
达不到就继续调材质明度，不要进入下一条。
输出改造前后的同角度静帧对比给我看。
```

## R2 — 工作台重建（先修 bug 再精细化）

```
放大帧显示工作台存在三个问题，先修 bug：

【Bug 1】桌面渲染成零厚度纸片。
配置里桌面是 0.65 × 0.60 × 0.06 m，但画面上完全看不到 0.06 m 的厚度，
边缘是刀刃状平面。请检查 spawn_textured_table_surface() 生成的 UV 薄层
是否覆盖/替代了真实桌面 box 的可视几何，或者真实桌面的 visual prim 是否根本没生成。
修复目标：桌面必须能看到明确的厚度和四条边缘。

【Bug 2】桌腿顶端与桌面之间有可见间隙。
make_scene_cfg() 里桌腿高度是根据桌面尺寸自动计算的，请核对这个计算是否
把 UV 薄层的 z 偏移算错了，导致桌腿顶面比桌面底面低了一个薄层厚度。
修复目标：桌腿顶面与桌面底面严格贴合，无缝隙。

【Bug 3】大理石纹理不可见。
桌面在画面上是纯白无纹理。原因可能是低对比浅灰纹理 + 曝光 1.15 过曝，
也可能是 UV 或纹理路径没生效。先诊断是哪一种：
把纹理临时换成高对比棋盘格测试图跑一帧，如果棋盘格可见就是对比度/曝光问题，
如果棋盘格也不可见就是 UV/材质路径问题。分别处理。

【修完 bug 后的精细化】
当前工作台是"一块板 + 四根方柱"，太简陋。升级为实验室工作台形态：
- 桌面加 3 mm 圆角边缘和一圈深色包边（包边亮度 ~110，与桌面 200 拉开）
- 四条腿改成方管型材外观，加横向下拉杆（前后各一根）构成框架
- 每条腿底部加地脚板 + 压板 + 4 个螺栓头（这些同时满足第一轮 P3 的要求）
- 桌面下方加一层网格置物板（可选，能显著提升"实验室家具"的可信度）
- 桌腿和框架统一用亮度 110 的深灰，与 platen 顶面 150 形成对比

所有新增几何 collision 禁用，只有原有的桌面和四条腿保留碰撞体。
```

## R3 — Stewart 机构重建

```
基坑里当前可见的机构不成立：一个孤立的浅色大球、几根互不相接的浅蓝灰圆柱、
一根来源不明的白色细杆，数量不足 6，连接关系读不出来，且颜色与基坑壁、
platen 混成一片。请按第一轮 P1 的规格重建，并额外注意以下几点：

1. 数量和对称性必须正确。六条腿，基座球铰按 6-3 分布（三对，每对间隔
   joint_pair_spread），台面球铰同样三对但相位错开 60°。
   从主视角看应该能清楚看出"六条腿两两成对、交叉排布"的经典 Stewart 拓扑。

2. 每条腿必须是连续的两段：外筒 + 活塞杆，两段共轴且有重叠段。
   当前画面里的圆柱是断开的。请在实现后渲一张纯几何线框图验证连接关系。

3. 球铰尺寸要合理。当前那个球明显过大（目测直径接近腿长的 1/4）。
   球铰直径建议取 rod_radius 的 2.0–2.5 倍，不要更大。

4. 删掉那根白色细杆，或者搞清楚它是什么。如果是某个调试可视化残留就移除。

5. 颜色按 R1 的明度规划：作动器筒 78，活塞杆略亮一点（~95，模拟镀铬），
   球铰最暗（~62）。三者必须能分辨。活塞杆比筒亮是关键——真实液压杆是
   镀铬亮面，这个明暗关系能直接读出"伸缩"这个语义。

6. 加上腿之间的交叉支撑和基座法兰盘，让机构看起来"撑得住"。

验收：
- 渲一段 platen 做纯 roll 摆动的 5 s 视频，六条腿的差动必须清晰可见。
- 渲一张从侧面平视的静帧，六条腿的拓扑关系必须能读懂。
- 第一轮 P1 要求的两项测试（反解长度解析一致、行程内）必须通过。
```

## R4 — platen 与基坑

```
【platen】
当前是一整块纯灰厚板，占据画面中心最大面积，是视觉上最空的元素。

- 按 R1 拆成顶板（亮度 150）+ 侧裙（亮度 95），并加 5 mm 倒角。
- 贴上第一轮 P3 规划的螺纹孔阵列纹理。注意：R1 做完之后这张贴图才有意义，
  孔洞的内壁阴影需要在 150 的底色上有足够对比才看得见，
  建议孔内壁烘焙到亮度 60–75。
- 侧裙加铭牌（型号 / 载荷 / "6-DOF SHAKER" 标识）和黄黑警示斜条。
- 四角加加速度计模型（对应第一轮 P6 的 IMU 观测通道）和吊环孔。
- 顶面靠近边缘处加两条深色分区线（安装区边界），增加表面信息密度。

【基坑】
当前基坑过浅、大面积空透，能直接看穿到底，platen 缺乏"被支撑"的说服力。

- 加深基坑，使 Stewart 机构的完整高度都在坑内，视线从主视角看过去
  应该被机构本身填满，而不是看到大片空的坑底。

- 坑口加一圈金属包边（亮度 ~90）和格栅盖板，不要现在这样直接一个方洞。
- 坑内加线缆：从机构底部引出几根粗线缆，沿坑壁走到一侧。
  这是填充空洞感最廉价有效的手段。
- 坑底加惯性基座（亮度 62），占据坑底大部分面积。
```

## R7 — 构图与叠加层

```
当前四个叠加面板占用约 40% 的画面，且左上标题面板直接遮挡了机械臂上半部分
（在 t=0.5s 和 t=5.5s 帧上都能看到机械臂的肘部被面板压住）。
振动 benchmark 视频的核心是"机械臂在振动中作业"，遮挡主体是本末倒置。

1. 标题面板：
   - 缩小到当前的 60%，移到左上角更靠边的位置，
     或改为只在前 2 s 显示然后淡出
   - "C2 floor: Panda + marble table + shallow bin + YCB/sugar_box" 这行
     信息密度低，可以删掉或缩短
   - 保留 phase / t / Delta-z / finger contact / excitation 这些运行时信息，
     但改成单行紧凑排版

2. 振动曲线面板：
   - 当前占据整个左下，缩小到 60% 宽
   - 加上第一轮 P7 要求的 a_rms_g 数值显示（当前默认谱是 6.22 g，
     这个数字应该醒目地放出来）
   - 曲线的三种颜色（tx/tz/rx）当前在深色背景上偏暗，提高亮度

3. 腕部相机画中画：位置合适，保持，但加一圈更细的边框

4. 主相机：
   - 当前俯角偏高、距离偏远，platen 作为一大块灰色占据画面中心。
     建议降低俯角约 10°、拉近一些，让机械臂和工作台占更大画面比例，
     并让基坑侧壁和 Stewart 机构进入画面（这是新增的最有价值的视觉资产，
     现在被 platen 挡住大半）
   - 考虑加一个缓慢的轨道运镜（14 s 内绕 15°），能显著提升"成熟演示"的观感，
     且不影响物理

5. 工件当前缩放 0.55 后在主视角中过小难辨。
   建议默认缩放提到 0.75，或在主视角里给工件加一个细的高亮描边/指示器。
```

## 2. 执行顺序与验收门槛

| 轮次 | 提示词 | 验收门槛 |
|---|---|---|
| 1 | R0 | 视觉审计脚本可用，基线已保存 |
| 2 | **R1** | **IQR ≥ 60、std ≥ 55、窄带占比 < 50%。不达标不得进入下一轮** |
| 3 | R2 + R3 | 桌面厚度可见、桌腿无缝隙、六腿拓扑可读 |
| 4 | R4 + R5 | 孔阵列在画面上可辨认、护栏不切割构图 |
| 5 | R6 + R7 | 机柜/椅子/线缆到位、机械臂不被叠加层遮挡 |

全程不变的约束：`pytest -q tests` 保持全绿、接触对数量增量为 0、第 14 节复现命令仍产出 `success=true`。

如果时间有限只能做两条：**R1 + R3**。R1 解决"所有东西糊在一起"，R3 让 6-DOF 这个卖点在画面上真正成立。这两条做完再回头看，你会发现原来以为需要的很多细节其实已经够了。
