能看到——仓库 `Blien2002/ShakeBench` 是公开的（Python，单次提交 `7dd5abd`，创建于 2026-08-17）。我把它克隆下来通读了 `vibration.py / mounting.py / task.py / config.py / scene.py / shaker.py` 和 `configs/`，并且把默认谱型按代码逻辑重新实现跑了一遍数值核对。

先提一句：README 和 CLAUDE.md 大量引用 `tests/`、`docs/`（第四轮验证记录、穿透基线、prim 锚点审计）和 `tools/`，但这三个目录**没有提交进仓库**，`run_tests.sh` 也没有对应的测试可跑。所以下面的判断只基于源码本身，无法用作者声称的验证证据交叉检验。

## 机制本身是什么

`SpectralVibration` 用每轴一个窄带、8–12 根随机相位谱线合成六自由度**位移**，解析求导得到速度/加速度；`mounting.c2_support_motions` 用 `p = t + Rr − r` 把地板中心运动映射到两个安装点；`task._write_supports()` 每个 1 ms 外循环步把机械臂浮动根节点、工作台、桌腿、目标盒、振动地板的位姿和速度**直接写进仿真**。Stewart 平台是纯视觉的（碰撞关闭）。

## 做得对的部分

多正弦合成的幅值缩放 `rms·√(2/N)` 是正确的（我实测各轴实现位移 RMS 与配置值吻合到 0.5% 以内）；五次 smoothstep 斜坡的位置/速度/加速度在 t=0 和 t=ramp 两端都是 C² 连续，乘积法则展开无误；`motion_at_mount` 用完整旋转矩阵而非一阶近似；`_mount_rotation` 与 `_support_state` 里 `quat_from_euler_xyz(rx, -ry, rz)` 的符号约定是一致的（Rz·Ry·Rx），没有"转两次"的错误；解析导数而非有限差分、种子可复现、把后端限制（NativeCCD 清零 margin）写进 JSON 而不是掩盖——这些工程纪律在同类仓库里算相当好。

## 主要问题（按严重程度）

**1. 安装点坐标系和可见几何不自洽，这是最实质的建模缺陷。**
`arm_mount_xy_m = (0.75, −0.45)` 但 `robot_base = (−0.47, 0, 0.08)`；`table_mount_xy_m = (−0.75, 0.45)` 但 `worktable_center = (0.18, 0, 0.34)`——两者**符号是反的**。而振动地板 prim 本身用的是中心运动。后果是"地板 + 臂 + 台"不再构成刚体：我按 seed 17 跑 16 s，Panda 基座与它正下方那块地板的竖向错位 RMS 2.9 mm、峰值 **11.9 mm**，而 `robot_mount_dynamic_clearance_m` 只给了 7 mm。也就是说俯仰峰值时基座会往可见地板里嵌进去几毫米。地板是碰撞体、`panda_link0` 也是，基座又是被逐步覆写的浮动根——单个子步内的深嵌会产生极大接触冲量并沿关节链传播。臂/台之间的竖向差动峰值 16.7 mm，而按**可见**的 0.65 m 间距刚性地板只该有 5 mm 左右，即差动被放大了约 3 倍。CLAUDE.md 说这个"测量坐标系与紧凑布局坐标系有意分离"，但看不出对随之而来的刚体不一致做过处理。

**2. 激励量级偏离真实工况很远，且被单轴主导。**

| 轴 | 中心频率 | 位移 RMS | 加速度 RMS | 位移峰值 |
|---|---|---|---|---|
| tz | 32 Hz | 1.50 mm | **60.7 m/s² ≈ 6.2 g** | 5.2 mm |
| tx | 18 Hz | 0.50 mm | 6.4 m/s² ≈ 0.65 g | 1.7 mm |
| ty | 13 Hz | 0.25 mm | 1.7 m/s² ≈ 0.17 g | 1.0 mm |
| rx | 8 Hz | 4.0 mrad | 10.2 rad/s² | 11.1 mrad |

6.2 g RMS 的窄带垂向激励，比 MIL-STD-810 轮式/履带车辆谱高一个量级，更接近共振驻留式振动台鉴定试验。整个难度几乎完全由 tz 一根带子和 rx/ry 转角决定，其余四轴基本是装饰。而且这里是按**位移 RMS** 配置带宽内等幅谱线，和振动工程惯用的加速度 PSD（g²/Hz）不是一回事，很难对应到任何标准谱。

**3. 安全门限的估计偏乐观，实际裕度接近零。**
`estimated_peak_velocity_m_s` 取 `3.5 × max(各轴 RMS 速度)`。问题是取了**各轴最大值而不是矢量合成**：六轴 RSS 是 0.385 m/s 而 max 只有 0.302 m/s。代码报 0.264 mm/子步、限值 0.300 mm，看着有 12% 余量；我实测挂载点真实最大 |v| 对应的子步位移是 seed 17 → 0.2875 mm、seed 0 → **0.3002 mm（已超限）**。另外估计用 `center_hz` 而不是抖动上边界（再少 8%）。结论不是数量级错误，但"通过"是两个近似误差偶然抵消的结果，不是有意留出的裕度。

**4. 「无限刚度基座 + 零重力机械臂」。**
`scene.py:91` 把 `disable_gravity = True` 加在了 Panda 上（Isaac Lab 默认是 False，这是本仓库主动改的）。工件仍受重力（`disable_gravity=False`）。于是臂在零重力下被一个完美运动源摇晃：没有静态下垂、关节力矩饱和不会被真实触发、臂的反作用也不会回馈给地板。同时解析加速度 `_vibration_qdd` 只进了 observation，**从未进入物理**——基座加速度实际上是以 1 kHz 的速度跳变形式施加的（4 个子步内保持不变，32 Hz 分量约 31 采样/周期）。作为"重型振动台 + 刚性安装"的简化可以接受，但它决定性地改变了难度来源，应该在 README 里写清楚而不是只写在 scene.py 注释里。

**5. 跨轴随机数复用（确定性 bug）。**
`vibration.py:97` 的 `rng = np.random.default_rng(seed + 1009*env_id)` 在 **`for axis` 循环内部**创建。同 `tones` 的轴拿到完全相同的抖动向量和相位向量。默认谱下我验证过：`tx / tz / rx` 相位完全相同，`ty / ry` 相同。频率不同所以时域波形有差异，但 t=0 附近各轴强相关（`q_tz(0)/A_tz = q_rx(0)/A_rx` 严格相等），"各轴独立随机"没有实现。改法很简单：`default_rng([seed, env_id, axis_index])`。

**6. 「精确」的说法与实现不一致。**
`velocity_at_mount` 的 docstring 写 "exact rigid-body velocity"，但 `ω = (ṙx, −ṙy, ṙz)` 是把欧拉角速率当角速度用的**小角度近似**（严格来说 ω = E(θ)θ̇）。毫弧度量级下误差 ~10 µm，可以忽略——但既然位置那边强调了完整 SE(3)、CLAUDE.md 也写"绝不用小角度近似"，这里应该改掉或者改注释。

**7. 穿透评分阈值等于离散化预算。**
`max_penetration_mm: 0.3` 与 `max_substep_displacement_m: 0.0003` 是同一个数，grasp assist 的门限是 0.5 mm / 1.0 mm。也就是说穿透指标在很大程度上度量的是求解器的时间离散误差，而不是抓取质量。要么把激励降下来（或提高子步率）拉开这两个量级，要么把穿透从"评分门限"降级为"诊断量"。

**8. 其他。** `solve_leg_transforms` 在行程越界时直接 `raise`，而它是在每步循环里被调用的——一次超程会中断整个 rollout，更合适的是 clamp + 记录到 metrics；`material_mu`（默认 1.5）对最关键的两个接触对不起作用，因为 platform 和 workpiece 在 `scene.py` 里硬编码了 0.8/0.8；`observed_vibration_displacement_rms` 只用了 4 s 环形缓冲，16 s 回合里只覆盖尾部。

## 如果要改，优先级

1. 让挂载点与可见几何一致（把 `arm_mount_xy_m` 改成 `robot_base[:2]`、`table_mount_xy_m` 改成 `worktable_center[:2]`，需要更大差动就把地板画大或显式建一个非刚性/多支撑柔性模型），或至少把地板 prim 也按同一映射写，别让"地板+臂+台"散架。
2. 修 RNG 复用。
3. 安全估计改成六轴矢量合成 + 用带上边界频率 + 用真实最不利力臂，并把限值和评分穿透阈值拉开 3–5 倍。
4. 把激励重新按加速度 PSD 定义并对标一个具体标准（MIL-STD-810 Method 514 某类，或 ISO 8608 路面），把 tz 的 6.2 g 降到可辩护的量级。
5. 机械臂重力打开（配 PD 增益重调），或者在文档里把"零重力臂"作为已知简化明确列出。
6. 把 `tests/`、`docs/`、`tools/` 提交进仓库——目前所有可信度都押在没有公开的验证记录上。

总体判断：**工程实现质量明显高于建模自洽性**。合成、求导、斜坡、种子复现、诚实评分这些做得很扎实；但支撑点坐标系与可见场景的不一致（第 1 条）、激励量级缺乏标准依据（第 2 条）、以及安全门限的实际零裕度（第 3 条）这三条叠加起来，会让"官方档位"报出的分数难以解释成对真实车载振动鲁棒性的度量。
