## 0. 怎么用这份文档

每个 `P` 段是一条独立提示词，设计为直接粘贴给 Claude Code / Cursor 执行。建议顺序执行，每条做完跑一次 `pytest -q tests` 和一次录制复现命令再进入下一条。

三条贯穿全程的硬约束，建议在每次开新会话时一并粘上：

```
硬约束（每条改造都必须满足）：
1. tests/test_vibration.py 当前 7 项测试必须继续通过。新增纹理必须同步更新
   configs/assets.yaml 的 SHA-256，否则第 6 项测试会挂。
2. 第 14 节的复现命令必须仍能跑通并产出 success=true 的 MP4 + JSON。
3. 物理后端是 Newton/MJWarp，不是 PhysX。所有"纯视觉"几何必须显式确认没有
   被 MJWarp 纳入接触对，改造前后打印一次接触对数量做对比。
```

## 1. 与当前实现的对齐结论

### 1.1 已经做好、不要重做的部分

这些是我在通用建议里会强调、但你已经解决的：

| 项 | 现状 |
|---|---|
| 机械臂浮动根 | `fix_root_link=False`，每步写 root pose + velocity。不用改 |
| 速度同步 | `_support_state()` 已用 `v_i = v_0 + ω × r_i` 解析计算，不是有限差分。不用改 |
| 激励可复现性 | `seed + 1009 × env_id`，谱线相位由 seed 决定，已有测试覆盖 |
| 平滑启动 | 0.75 s 五次 smoothstep，且对 `q/qd/qdd` 按乘积法则同步作用 |
| 多测点耦合 | C2 映射让机械臂侧和工作台侧产生不同局部平动，这一点比多数同类工作做得细 |
| 采样率余量 | 240 Hz × 4 子步 = 960 Hz 有效，对当前最高 32 Hz 频带有 30 倍过采样，充裕 |
| 房间与纹理管线 | Arena 风格布局/样式分离 + 本地固化 CC0 纹理 + 哈希测试，工程化程度已经不错 |
| 腕部相机 | 有物理外壳、固定手眼外参、完整滚转自由度，不是虚拟视角 |

### 1.2 主要 gap

按对"看起来是成熟 benchmark"的贡献度排序：

1. **振动台没有硬件形态。** `1.60 × 1.10 × 0.08 m` 的运动学地板就是你说的"灰色平板"。6-DOF 是靠脚本驱动实现的，但场景里看不到任何产生 6-DOF 运动的机构。这是当前最大的视觉短板。
2. **NewtonGL 的渲染约束没有被针对性利用。** 关闭了硬阴影、没有 PBR/HDRI/法线贴图路径，真实感只能来自**几何 + 烘焙进 albedo 的明暗**。当前策略还停留在"贴一张平色纹理"。
3. **房间尺度偏小且缺中景。** `3.60 × 3.10 × 2.30 m` 更像一间办公室而不是振动实验室，且没有控制柜、线缆、围栏等提供深度线索的中景物体。
4. **激励缺少难度分级和标准对标。** 只有 `off / sine / spectral` 三档，没有 L0–L4 分级，没有向 IEC 60068-2-6 / MIL-STD-810 谱型的映射，也没有报告加速度 RMS。
5. **观测构型单一。** 只有随臂振动的腕部相机 + 录制主视角，缺台外静止相机作为对照。
6. **评测协议未定型。** `grasp_assist` 默认开启，没有批量评测脚本，没有性能随振动强度的退化曲线。

### 1.3 两个立刻可用的量化结论

**你的默认谱比看上去猛。** 窄带谱下 `a_rms = d_rms · ω²`：

| 轴 | 中心频率 | 位移 RMS | 加速度 RMS |
|---|---:|---:|---:|
| `tx` | 18 Hz | 0.50 mm | 0.65 g |
| `ty` | 13 Hz | 0.25 mm | 0.17 g |
| `tz` | 32 Hz | 1.50 mm | **6.18 g** |
| 合成平动 | — | — | **6.22 g** |

6.2 g RMS 已经接近严苛运输/军用环境量级。**强烈建议在 JSON 和视频叠加里直接报告 `a_rms_g`**，而不是只报位移 mm——审稿人和同行看的是 g，而且这个数字对你有利。代码里已有 `qdd` 解析导数，直接统计即可，不需要新算法。

**C2 小角度近似目前安全，但做难度分级时会失效。** `mounting.py` 用的是一阶近似，忽略了 `(1-cos θ)` 项。在 `x = 0.75 m` 安装点处的 z 向系统误差：

| 角度幅值 | z 误差 | 占 tz RMS 比例 |
|---:|---:|---:|
| 4 mrad（当前） | 6 µm | 0.4% |
| 10 mrad | 38 µm | 2.5% |
| 20 mrad | 150 µm | 10% |
| 50 mrad | 937 µm | **62%** |

当前完全没问题。但 L3/L4 一旦把角度推到 20 mrad 以上，这个近似会引入比信号本身还大的误差。见 P7。

## P1 — 振动台硬件化：Stewart 平台（核心改造）

```
把当前的灰色运动学地板升级成完整的 6-DOF Stewart 平台（六足）硬件形态。

设计前提（必须严格遵守）：
- platen（台面）继续由 SpectralVibration + C2 映射运动学驱动，驱动逻辑完全不变。
- 六条腿、基座平台、惯性基座、隔振气囊全部是"跟随者"，纯视觉，不参与物理，
  绝不能反向影响 platen 的运动。
- 不要建真实闭链机构。Stewart 平台是闭链，在 MJWarp 里需要 loop closure 约束，
  数值不稳且严重拖慢仿真，收益为负。

新建 src/vibench/shaker.py，实现：

1. ShakerGeometryCfg（configclass）：
   - base_joint_radius（基座球铰分布圆半径，默认 0.75 m）
   - platen_joint_radius（台面球铰分布圆半径，默认 0.55 m）
   - joint_pair_spread（每对球铰的角度间隔，默认 20°，形成经典的 6-3 分布）
   - leg_stroke_nominal / leg_stroke_min / leg_stroke_max（行程限位）
   - cylinder_radius / rod_radius

2. 每条腿由两段刚体组成，做伸缩式外观：
   - 外筒：一端固定在基座球铰，沿腿轴方向，长度固定
   - 活塞杆：一端固定在台面球铰，沿腿轴方向，长度固定
   - 两段沿同一轴线重叠，重叠量随腿长变化 —— 这样用两个定长刚体就能表现变长度的作动器，
     不需要可变形几何。
   - 两端各加一个小球体表示万向节。

3. solve_leg_transforms(platen_pose) -> 6 × (外筒位姿, 活塞杆位姿, 腿长)：
   纯几何反解。基座球铰点在世界系固定，台面球铰点随 platen 位姿变换，
   腿向量 = 台面球铰点 - 基座球铰点。这是解析计算，不需要迭代求解器。
   如果任何一条腿长度超出 [leg_stroke_min, leg_stroke_max]，抛异常并打印是哪条腿、
   当前长度、当前 platen 位姿 —— 不要静默截断。

4. 基座平台（六边形厚板）+ 惯性基座（大质量块）+ 六个隔振气囊（矮圆柱），
   全部固定在世界系，不运动。

集成：
- 所有腿段/基座/气囊建成 kinematic rigid body，collision 完全禁用，
  沿用 task.py 现有 _write_supports() 的写入模式，每步追加写入 12 个腿段位姿。
- 改造前后必须打印 MJWarp 接触对数量对比，增量应为 0。若不为 0，说明 collision
  没有真正禁用，必须解决后才算完成。

验收：
- 在 tests/test_vibration.py 新增两项测试：
  (a) 给定一组 platen 位姿，六条腿的反解长度与手工推导的解析值一致；
  (b) 在 spectral 模式默认谱下跑 1000 步，六条腿长度始终在行程内。
- 录一段 10 s 视频，platen 做纯 roll 摆动时，六条腿长度必须呈现明显差动
  （不能六条同步伸缩）。
```

## P2 — 安装高度与房间重构

```
Stewart 平台需要垂直空间，但当前房间只有 2.30 m 层高，Panda 直接抬高会顶到天花板。

采用下沉式（基坑）安装方案：

- 在房间地面开一个矩形基坑，惯性基座、六个隔振气囊、基座平台、六条腿的下半部分
  全部位于基坑内。
- platen 上表面高出房间地面 0.25 m 左右，四周加一圈踏步平台/格栅盖板。
- 关键收益：Panda 基座的世界高度相对当前几乎不变，controller.py 的 IK 航点、
  抓取高度、状态机各阶段时长全部不需要重调。这是选下沉式而不是抬升式的主要原因。
- 基坑边缘加安全护栏（四周，靠近相机一侧做半高或留缺口以免遮挡主视角）。

同时扩大房间，当前 3.60 × 3.10 × 2.30 m 更像办公室：
- 目标尺寸 6.0 × 5.0 × 3.0 m。
- 保持 configs/room.yaml 的"布局与样式分离"结构，只改数值和新增基坑/护栏段，
  不要破坏 load_room_arena_cfg() 的确定性加载（测试 5 依赖它）。

- 重新标定 recording.py 里主相机的位置和朝向，保证平台、机械臂、工作台、目标盒
  都在画面内且构图合理。

  背景过暗或机械臂与墙面糊在一起。
- 改完录一段视频给我看效果，不要直接进入下一步。
```

## P4 — NewtonGL 约束下的真实感策略

```
这一步专门针对 NewtonGL 的渲染限制。当前打光是 sky(0.30) + ground(0.22) 环境光
+ 白色斜上主光 + 相机方向补光，关闭了硬投影阴影，曝光 1.15，镜面 0.22。

无阴影是当前"塑料感"的最大来源 —— 物体和地面之间没有接触感，看起来像悬浮。

1. 假接触阴影（优先做，收益最大）：
   实现 spawn_contact_shadow_decal()，在以下位置生成半透明深色薄 quad
   （沿用 visual_assets.py 的 author_textured_quad() 0.2 mm 封闭网格方案）：
   - 工作台四条桌腿下方
   - 目标盒下方
   - platen 下方（投在基坑底）
   - 工件下方（这一个需要每步跟随工件位姿，且抬起后要按高度衰减透明度/放大半径）
   贴图用径向渐变的软阴影，中心不透明度约 0.45，边缘为 0。

2. 材质差异靠 albedo：
   根据 P0 的能力探测结论，如果 roughness/metallic 不生效，就把材质区分烘进贴图 ——
   金属件用更高对比度和明显的高光条带，橡胶件用低对比度深色哑光，
   木地板保持现状。给每张贴图预烘焙一层 AO（角落、接缝、孔洞内壁压暗）。

3. 打光微调：
   - 增加一盏低强度背光（从机械臂后上方打），做轮廓分离，避免深色机械臂和墙面糊在一起。
   - 环境光的 sky/ground 比值可以拉大一点（例如 sky 0.34 / ground 0.18），
     增强"上方来光"的方向感。
   - 每改一版都渲一张静帧对比，不要一次改完。

4. 如果 P0 探测发现 NewtonGL 完全不支持多光源，就把方向性完全烘进贴图，
   并在文档里明确记录这个限制。
```

## P7 — 难度分级、标准谱对标与 C2 精度

```
分四部分，第 4 部分是正确性问题，优先级最高。

1. 报告加速度 RMS：
   当前配置用位移 RMS（mm）描述强度，但振动领域和所有标准都用加速度 RMS（g）。
   窄带谱下 a_rms = d_rms · ω²，代码里已有解析 qdd，直接对谱线求和即可精确计算。
   实测当前默认谱：tx 0.65 g / ty 0.17 g / tz 6.18 g / 合成平动 6.22 g。
   请在 VibrationConfig 里加一个只读属性输出各轴和合成的 a_rms（m/s² 与 g），
   并写进 JSON 指标和视频叠加。这个数字对项目有利，应该显式展示。

2. 难度分级 L0–L4：
   按台面合成加速度 RMS 分级，而不是按位移。同时区分主导方向
   （pure_vertical / pure_horizontal / full_6dof）。
   L0 = 静止对照组。当前默认谱大约落在 L3–L4 之间，请以它为锚点向下补齐 L1/L2。
   分级定义写进 configs/scenarios.yaml，扩展成完整场景矩阵。

3. 新增激励模式：
   - sine_sweep：对数或线性扫频，可配 f_start / f_end / sweep_rate，
     位移、速度、加速度同样走解析求导，不要有限差分。
   - shock：半正弦冲击脉冲，可配峰值 g 和脉宽。
     注意：加这个模式前必须核算 240 Hz × 4 子步的有效采样率能否表达指定脉宽，
     不满足就在启动时报错，不要静默失真。
   - replay：读外部 CSV 的实测六轴时序，做样条插值和解析求导。
   在 configs/scenarios.yaml 里给出向 IEC 60068-2-6 和 MIL-STD-810 常见谱型的
   映射说明（作为文档注释，不需要声称已完成标准符合性认证）。

4. C2 小角度近似的精度边界（正确性问题）：
   mounting.py 当前用一阶近似 tz_i = tz + x·ry + y·rx，忽略了 (1-cos θ) 项。
   在 x = 0.75 m 安装点处的 z 向系统误差：
     4 mrad（当前）→ 6 µm，占 tz RMS 的 0.4%，可忽略
     20 mrad → 150 µm，占 10%
     50 mrad → 937 µm，占 62%，近似彻底失效
   L3/L4 一旦提高角度幅值，这个近似会引入比信号本身还大的误差。
   请把 mounting.py 改成完整 SE(3) 变换（用旋转矩阵/四元数直接变换安装点位置，
   速度用 v_i = v_0 + ω × r_i 保持不变，这部分已经是精确的）。
   改完后新增一项测试：在 4 mrad 下新旧实现结果一致（误差 < 1 µm），
   在 50 mrad 下新实现与解析真值一致而旧实现偏差超过 900 µm。
```

## 2. Newton / MJWarp 栈上的关键陷阱

| # | 陷阱 | 说明 |
|---|---|---|
| 1 | 纯视觉几何被卷入接触 | `author_textured_quad()` 用 0.2 mm 封闭网格已经说明 MJWarp 对薄面片敏感。新增的六条腿、机柜、线缆若未真正禁用 collision，会大幅拖慢并可能产生穿插。每次改造都要对比接触对数量 |
| 2 | 惯性基座不能有真实动力学 | platen 是运动学驱动的。如果给隔振气囊/惯性基座建真实动力学，会出现"基座反推台面"的逻辑矛盾。它们必须是纯视觉跟随者 |
| 3 | 采样率余量在加冲击后会消失 | 240 Hz × 4 子步对 32 Hz 谱有 30 倍余量，但半正弦冲击的等效带宽远高于其脉宽倒数，加 `shock` 模式前必须重新核算 |
| 4 | 位移 RMS ≠ 强度指标 | 对外报告一律用加速度 RMS（g）。当前默认谱是 6.22 g，位移只有 1.5 mm，只报位移会严重低估你的工作难度 |
| 5 | C2 一阶近似有角度上限 | 见 P7 第 4 条。安全阈值约 10 mrad；超过 20 mrad 必须换完整 SE(3) |
| 6 | 纹理哈希测试会挡住新资产 | 任何新增纹理都要同步 `configs/assets.yaml` 的 SHA-256，否则测试 6 直接失败 |
| 7 | NewtonGL 无阴影 = 悬浮感 | 这是当前视觉最大短板。假接触阴影贴片（P4 第 1 条）的收益远大于继续调材质参数 |
| 8 | 房间放大会破坏已调好的构图 | 主相机位置和主光角度是针对 3.6 × 3.1 m 房间调的，P2 之后必须重标定 |
