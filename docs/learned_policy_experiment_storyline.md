# ShakeBench：学习策略实验主线建议

日期：2026-09-11。状态：研究设计提案，尚未执行，不替代已冻结协议或发布计分资格。

本方案基于当前仓库、用户报告的服务器静态门通过，以及下文链接的一手文献。WAM 指 DreamZero 一类 World Action Model；目前未确定 checkpoint、GPU 配置和训练数据。文中的效应均为待检验问题，不能写成已有 Finding。

## 1. 研究定位与路线选择

**建议把文章定位为：持续物理振动下学习策略的闭环鲁棒性 benchmark。主线是刻画能力边界，通过“训练经历 × 反馈时效”的受控实验解释边界，再检验改进能否跨振动分布迁移。**

中心问题：一个已经会完成静态任务的策略，在环境持续变化、接触状态受到扰动时，能否及时修正行为并完成任务？失败主要对哪种干预敏感：补充振动经历、缩短开环执行时间，还是二者结合？

这里“最有科学价值”是根据可区分的竞争解释、结果的信息量与当前实现成本作出的判断，不是对审稿结果的保证。

| 候选路线 | 能回答的问题 | 主要不足 | 建议地位 |
| --- | --- | --- | --- |
| V0–V3 oracle 的 Gamma 曲线与排名 | 一个手工控制器如何利用更多振动信息 | 结论依赖该控制器，难代表学习策略 | 环境资格、演示生成、局部诊断 |
| 许多 VLA/WAM 的振动排行榜 | 哪些 checkpoint 在指定条件下更稳健 | 排名变化难解释，易混入静态能力、输入和执行频率差异 | 必须有的总体结果表，但不是全部主线 |
| 振动后训练，再测未见 Gamma | 针对性训练是否有用 | 单独的域随机化收益不足以解释能力边界 | 关键干预之一 |
| 物理扰动评测 + 数据与反馈交叉干预 + 分布外确认 | 什么失效、哪些改动能修复、修复在哪里失效 | 要求严格配对和明确时间协议 | **推荐主线** |

不要预设 WAM 应该胜过 VLA，也不要要求每个物体、每种振动都出现退化。可复现的负结果同样能排除解释。

## 2. 相关工作划定的空间

以下是本轮核对到的直接相关一手资料，不是穷尽式新颖性审计。表格列出各工作的评测重点；不能仅凭摘要未提及某项就断言其完全不支持。

| [Colosseum V2](https://colosseum-v2.github.io/) | 视觉、语言、动作扰动及跨机器人形态泛化 | 可重放物理振动与策略执行时序的交互 |
| [LIBERO-RECOVER](https://arxiv.org/abs/2609.05178) | 由执行失败构建的恢复场景 | 干扰持续存在时完成任务与恢复的能力 |

因此，不应把 gap 写成“现有 benchmark 都没有扰动”或“没有人测恢复”。更稳妥的表述是：**需要一个将持续、可校准的物理激励与策略训练经历、闭环执行时序联系起来的评测协议。** 这一定位仍应在正式写稿前补做全面文献核查。

反馈与推理延迟也已有明确先例。[RTC](https://www.pi.website/research/real_time_chunking) 研究 action chunking 的异步执行和延迟鲁棒性；[DreamActVLA 项目](https://dream-act-vla.github.io/) 探索延迟观测与动态物体任务，页面注明其为课程项目。因此，单独观察“长 chunk 更差”不能作为独立新颖性主张；有价值的是它与真实接触扰动、训练经历和跨分布泛化的联合证据。

## 3. 仓库现状与 Phase 9.5 的取舍

- 以用户报告为准：服务器上已完成当前配置的静态门。本地 `phase_09_pilot_report.md` 和资格 manifest 仍是旧几何的 INVALIDATED 记录；本轮没有拿到服务器原始产物进行核验，不能据此否定服务器结果，也不能自行改写为 PASS。
- 当前是一个 `pick_place` 任务、三个物体 × 两种表面，共六种配置。六种配置不是六个不同任务。
- 原 Phase 9.5 先在 V0 上做每个 Gamma 600 states 的 knee 标定，再做 V0–V3 × 400 states 的正式测量。按用户给出的每次 3 分钟估算，后者是 80 小时串行 rollout 时间；前者每增加一个 Gamma 是 30 小时，尚不含训练或新模型推理。
- V0–V3 是 State 观测层级，包含物体真值位姿。环境明确禁止这些层级同时启用相机观测。已有相机演示不能自动视作视觉策略接口或视觉训练数据。
- 现有任务、物理、激励、metrics、outcome、state 配对和重放能力值得复用；现有 oracle runner 与 trace/verifier 绑定 FSM 字段，接入学习策略时需要保留环境评分语义、补充策略无关的运行记录。

**建议暂停原版 9.5 的大规模 knee 与四层 oracle 排名，保留资格认证与协议冻结工作。** 没有必要用某个 oracle 的 SR=0.5 来定义所有学习模型的唯一测量点；它可能对另一个模型是天花板或地板，也可能在当前范围内根本不存在。

之后应另行发布学习策略协议：保留输入身份、物理与成功判据的冻结和核验，新增 policy checkpoint、视觉输入、训练 split 与动作时序定义。不能直接翻转旧资产的 `scoreable` 标记，或把新实验冒充旧 9.5 的正式结果。

## 4. 三个 RQ 与实验顺序

### RQ1：在静态任务能力相近或已充分适配后，学习策略的振动鲁棒性边界在哪里？

先测总体能力，不急于发明训练方法。对同一 checkpoint、同一组初始状态配对测试静态、同谱不同强度、不同频谱条件。主表报告绝对成功率，同时报告相对静态的配对变化、分配置结果和失败阶段。

第一轮建议包含传统视觉策略、VLA、WAM 三类；先让一个传统策略与一个 VLA 跑通，再加入 WAM。若希望讨论模型家族差异，优先增加第二个 VLA checkpoint，而非把一个模型的多个训练版本算成多种模型。单个 WAM 与单个 VLA 的差异只能归因到这两个系统，不能直接归因到预训练范式。

开发集上的静态表现必须先足以支持振动分析；例如把 80%–90% 作为接入成熟度的开发目标，而非隐藏低分模型的筛选规则。若静态已很差，应先诊断相机、动作归一化、夹爪语义、示范质量与域适配；该结果仍需保留，不能把低振动 SR 全归因于振动。

**图表：** 模型 × 条件的总体表；固定频谱下的 SR–Gamma 曲线；物体/表面 × 失败阶段的分解。只用三四个冻结的强度点即可起步，不为寻找漂亮 knee 做密集扫描。

**可检验结果：** 静态高分是否伴随振动高分；相近 Gamma 的不同频谱是否表现不同；下降集中于接近抓取、持物搬运还是释放后稳定。没有排名反转也应保留结果。

### RQ2：补充振动经历与改善反馈时效，分别能修复多少退化？二者是替代还是互补？

这是论文最值得投入的受控实验。对同一模型，从同一静态适配 checkpoint 出发，建立以下 2 × 2 对照。

| | 默认执行前缀 H | 更短执行前缀 h |
| --- | --- | --- |
| 等预算静态继续训练 S | S,H：对照 | S,h：只改善重新观测/规划机会 |
| 等预算振动混合继续训练 V | V,H：只改变训练经历 | V,h：两种干预结合 |

H/h 是一次预测后实际执行多少动作才重新观测，不是模型预测序列的总长度，也不是底层控制频率。例如在当前 20 Hz 控制接口下，若模型支持，可先比较执行 4 步与 1 步，即 200 ms 与 50 ms。数值在开发集上核对可用后冻结；保持预测长度、动作单位、控制器、平滑方式和去噪设置一致。

静态和振动条件都必须跑这四格。否则短前缀在所有任务中普遍受益，会被误写成解决振动问题。

建议直接估计每个条件 c 的效应：

- 数据效应：`D(c) = SR(V,H,c) - SR(S,H,c)`。
- 反馈效应：`F(c) = SR(S,h,c) - SR(S,H,c)`。
- 交互：`I(c) = [SR(V,h,c) - SR(V,H,c)] - [SR(S,h,c) - SR(S,H,c)]`。
- 再比较 `D(c)-D(static)`、`F(c)-F(static)`，识别超出静态改进的收益。

交互使用百分点尺度并给区间，不从单个正数断言协同。如果出现天花板/地板，交互解释要同时查看四格绝对值。

这组实验允许多种有信息量的答案：数据有效而反馈无效；反馈有效而数据无效；二者必须结合；两者都无法解决某些接触失效。效应反映对所选干预的敏感性，不是将全部失败唯一分解成“数据不足”和“控制不足”。

**时间语义是必要控制。** 主诊断可采用明确标注的零额外推理延迟，隔离执行前缀的影响；这种理想短前缀不代表大型模型能在真实硬件上达到相应频率。再在少量代表条件上固定前缀、单独注入整步观测/动作延迟，并加入一个可实现的执行配置确认关键结论。

不能把“仿真暂停等模型返回”的结果当作实时能力，也不能让仿真按机器当时墙钟速度改变振动。部署条件应在固定硬件上测量预热后的推理延迟，并用明确的模拟时间调度实现；同时写清旧动作如何持续执行、队列如何更新、过期动作如何处理。WAM 和 VLA 的原生运行配置可以单独报告，不与统一诊断设置混成一种分数。

**图表：** 四格效应图，静态/同分布振动/未见振动并列；辅以少量延迟敏感性曲线。不要只给“我们训练后的模型最好”的柱状图。

### RQ3：上述改进能否迁移到未见振动，还是只适应了训练波形？

复用 RQ2 四格，在预先保留的振动条件上评测，检查数据效应、反馈效应及其交互是否仍存在，同时检验静态能力是否受损。无需为这一节额外发明算法。

| 测试条件 | 相对于振动训练的含义 | 支持的结论 |
| --- | --- | --- |
| 相同频谱/强度分布，新初始状态与新 seed | 同分布测试 | 泛化到新轨迹，不能称跨振动模式 |
| 同频谱，训练强度之间的新数值 | 强度插值 | 局部插值能力 |
| 同频谱，超出训练强度范围但处于已验证物理范围 | 强度外推 | 更强扰动的泛化 |
| 保留频谱或波形参数组，强度范围重叠 | 频谱/模式迁移 | 对未训练动态结构的泛化 |
| 保留频谱与外推强度同时改变 | 联合偏移 | 组合鲁棒性，不能单独归因于某一轴 |

例如：训练 A 频谱下 `Gamma={0.15,0.45}`，核心测试采用静态、A/0.45 新 seed、A/0.75、B/中等强度；A/0.30 是可选插值诊断。**这些数值仅是候选，须经物理响应与开发集有效性核对，不能视作已认证 safe range。**

先利用现有频谱配置能力做参数组留出。新增间歇、突变或其他波形需要额外实现和认证，不能把改 seed 称作新模式。当前配置存在 8.87 Hz 的频率上限，不能直接提高频率越过已认证范围。

若后续要比较“单一频谱训练”与“多频谱训练”，两者必须等数据预算；另外保留第三个频谱 C。B 一旦进入多频谱训练，就不能继续作为该模型的 OOD 证据。

**图表：** 训练条件 × 测试条件迁移表，以及各条件的配对收益与静态保留率。最终 Finding 由结果决定，不能提前写“振动后训练获得普适物理理解”。

## 5. 物理、数据与统计协议

### 物理强度与频谱

Gamma 在现有实现中来自给定程序、参考点、法向与校准窗口的加速度峰值归一化。它不是跨波形通用难度，更不是跨车船飞机的等效等级。[校准实现](/home/miracle04/Desktop/ShakeBench/robosuite/utils/shakebench_calibration.py:177)

主表同时保存 commanded Gamma、实际 deck/table 响应、六轴加速度 RMS/峰值、主要频谱、平移位移与转动幅度。跨频谱比较预先指定主要强度匹配量和容差，并报告剩余差异；不能只让 commanded Gamma 相同就宣称完全匹配。

改变频率还会改变位移、速度和接触响应，不能把整条跨频谱差异解释成纯“反馈带宽效应”。RQ2 在同一激励内改变执行时序，才提供更直接的干预证据。标定失败或执行无效与有效但任务失败分开记录，不因模型失败而删除物理有效条件。

### 训练数据

先建立共同静态适配模型，再从同一 checkpoint 做 S/V 分支。S 使用新的静态示范；V 用固定比例的静态与振动示范替换 S 的等量训练样本，例如振动占 50%，比例只在开发集确定。两支共享原静态数据的 replay 比例和初始化，匹配后训练更新数、有效动作样本数、采样策略与调参预算。

不同长度 episode 不能仅靠“示范条数相同”声称训练预算相同；同时报告唯一轨迹数、有效 transition 数、环境采集时间与训练 GPU 时间。模型家族之间无法抹平历史预训练差异，关键因果比较应在模型内部进行。

oracle 的主要用途变为训练示范和资格见证。采集 RGB、proprioception、指令、实际执行动作、时间戳与环境成功证据。保留成功 episode 中真实发生的纠错；普通 BC/SFT 不应把最终失败的动作片段直接当作正确示范。记录所有采集尝试、失败原因、成功筛选规则及各条件示范产率，防止只学到“容易振动”的样本。

不把静态视频加抖动后的图像当作真实振动动作标签。若重放旧轨迹补渲染，必须验证相同状态、激励与动作重现原轨迹；重渲染也有成本。服务器静态门的结果 JSON 不等于已具备可训练视觉数据。

先按独立 parent/episode 划分 train、validation、test，再展开物体/表面和轨迹窗口。同一轨迹的相邻帧不能跨 split；保留测试激励 seed、参数组和评测状态，所有归一化统计只用训练集。已有 knee/pilot 数据用于开发；若使用冻结 official states 的子集，按与结果无关的规则事先生成独立版本，保留原资产，不把它冒称原 400-state official measurement。

### 输入与评分

主视觉评测只提供冻结的相机输入、可获得的机器人本体状态和任务指令。物体真值、接触真值、未来激励、evaluator metrics 留在评分侧；State oracle 单列。相机的安装坐标系、分辨率、历史窗口以及每个模型实际使用的视图必须记录。视频型模型接入时还要核对视频帧率与动作频率，不通过随意重采样改变动作物理时间。

IMU 可以作为后续传感增益实验，但应在同一骨干、同一训练预算下重新训练输入分支，不在测试时突然给原模型新增通道。

主指标是完整任务成功率，保留现有释放后稳定与违规判定。Gamma 曲线、相对静态降幅、分阶段失败与恢复属于解释性指标。若需要单一排名，使用预注册条件与权重的平均 SR；不同协议版本的分数不能直接混排。分布外各项仍需单独展示，避免平均值掩盖失败。

失败阶段由环境侧物体/接触/末端事件定义，不依赖 oracle 自己的 FSM 阶段名。至少区分未建立抓持、持物中失去抓持、目标外释放、释放后失稳和超时；允许未知/多事件标签。阶段暴露数、事件数与恢复分母一起报告，避免只分析成功抵达某阶段的样本。

### 统计与不确定性

所有模型和干预尽量共享完整 state 与激励身份，采用配对差值。六个 variant 若来自同一 parent，不是六个独立种子；应按 parent 聚类 bootstrap。若使用每 parent 一种配置的独立状态池，则按该设计配对，不能假称配置之间完全配对。

环境随机性、策略采样随机性与训练 seed 分开记录。开发实验可以先用一个训练 seed；关键后训练结论应由多个独立训练重复确认，不能用数百次同一 checkpoint rollout 代替训练重复。报告效应和区间，不只报告 p 值。

小样本用于发现大的效应。例如 48 个独立二元结果在 SR 约 50% 时，普通单组 95% 区间半宽约 14 个百分点；配对差值精度取决于不一致对的数量。这不足以可靠争论两三个百分点的排名。正式规模依据开发集方差与预定最小有意义效应确定，不能在测试集上反复加样直到显著。

## 6. 模型选择与增量实验的优先级

| 角色 | 候选 | 入选目的 |
| --- | --- | --- |
| 传统学习策略 | [Diffusion Policy](https://diffusion-policy.cs.columbia.edu/) | 提供不依赖大型视觉语言预训练的视觉策略参照，便于先验证学习闭环 |
| VLA 1 | [OpenVLA-OFT](https://openvla-oft.github.io/) | 已提供后训练与机器人评测路径的候选 |
| VLA 2 | [openpi 的 π 系列](https://github.com/Physical-Intelligence/openpi) | 增加不同 VLA 系统的覆盖，避免所有结论依赖单一 checkpoint |
| WAM | [DreamZero](https://github.com/dreamzero0/dreamzero) | 测试联合视频/动作建模系统在同一物理扰动下的表现 |

候选不等于当前 ShakeBench 已兼容。DreamZero 官方代码提供训练/后训练路径，其 README 的分布式推理配置要求多 GPU，且机器人输入、视图与动作需要适配；应在确认 GPU 与 checkpoint 后决定具体接入顺序。不能将其他平台上的成功率或延迟直接移植到本项目。

若只能追加一块工作，优先顺序取决于要保留的主张：

1. 对当前主线：先补关键 2×2 对照和训练重复；这直接影响解释是否可信。
2. 对“操作 benchmark”的广泛主张：增加第二种接触结构不同的任务，例如受振堆叠，而非把六种 pick-place 配置当成多任务。仓库已有 `Stack` 环境，但接入振动和认证仍需工作。否则将论文范围明确限定为 pick-and-place。
3. 对现实适用性：若有硬件，做少量模拟/实物的配对趋势验证，或使用实测激励并核对仿真响应。仅播放实测波形不能称真实机器人验证。
4. 之后再考虑多频谱数据多样性、IMU/历史信息消融、数据量曲线与更多模型尺寸。

不机械套用通用 LLM benchmark 的“10–15 个模型”“最难集必须低于某个成功率”等数量建议。应优先覆盖有区别的策略和物理条件，并保留足够样本来区分核心解释。

## 7. 预算与近期执行顺序

改变主线是在提高每次 rollout 的信息量，不代表学习实验的总成本一定更低。以下均按 3 分钟/episode 的串行等价估算；渲染、模型推理、数据筛选、训练、失败重试与硬件吞吐需另计，不能承诺线性并行加速。

| 阶段 | 规模示例 | rollout 等价耗时 | 能支持什么 |
| --- | --- | --- | --- |
| 补完既有 Phase 09 资格 | 60 正振动 + 18 重放 = 78 | 3.9 h | 当前环境和记录可用 |
| 首个学习闭环 pilot | 1 模型 × 2 训练条件 × 2 执行前缀 × 4 环境条件 × 12 states = 192 | 9.6 h | 接口、训练和大效应探索，不能作为稳定排名 |
| 核心交叉实验 | 2 模型 × 2 训练条件 × 2 执行前缀 × 4 环境条件 × 48 states = 1,536 | 76.8 h | 一个训练 seed 下，围绕 RQ2/RQ3 的核心数据 |
| 同矩阵三个训练 seed | 1,536 × 3 = 4,608 | 230.4 h | 增加训练重复证据，仍需按效应检查精度 |

四个核心环境条件是静态、A 中等强度新 seed、A 强度外推、B 保留频谱。12/48 states 应事前按六配置均衡，优先每个 parent 一种配置并跨实验严格配对；不要把很少的共享 parent 展开后冒充更大独立样本。

训练数据也要单列预算。示例起点可以是 60 条基础静态成功示范、60 条额外静态示范、60 条振动示范，供共享初始化与 S/V 分支复用；即使一次采集就成功也相当于 180 次、9 小时，实际会因成功率与成像成本增加。这只是闭环试验起点，不保证足够训练 VLA/WAM。先测开发集学习曲线与采集产率，再决定增加数据还是修接口。

执行顺序：

1. 核对并接回服务器静态门证据；完成有限的正振动 pilot 与重放。
2. 冻结视觉输入/动作时间/成功判据，先取得一个学习策略可靠的静态表现。
3. 用 192 次量级的开发 pilot 检查四格和迁移条件是否可执行，连同实际训练与推理成本一起评估。
4. 根据开发证据冻结论文的模型池、物理条件、最小有意义效应与正式预算，再运行保留测试集。
5. 将预算优先分给关键交叉对照、训练重复、任务覆盖；oracle 密集 Gamma 扫描不再是前置依赖。

若所有模型静态都差，先解决接入/学习；若所有振动条件都无区别或全失败，先核对激励响应与任务可解性，并在开发阶段调整覆盖。保留全部开发记录，不用正式测试结果追选能支持某个结论的条件。若后训练不能泛化，这是可报告的能力边界，不构成环境资格失败。
